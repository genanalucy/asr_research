# DDP启动失败与四seed回退记录

日期：2026-10-14，北京时间。用户要求使用四张空闲GPU加速最佳学习率训练。原计划是四卡联合DDP；实际服务器在最小化NCCL测试中于 `ncclCommInitRank` 阶段SIGSEGV，2卡/4卡均复现，Gloo GPU测试也未通过。故本轮不能把DDP失败归因于ASR模型或数据，也不降低门槛重试。

## 失败证据

- 服务器：hzh@10.240.147.134，torch2.6.0+cu124，NCCL2.21.5。
- DDP命令：`CUDA_VISIBLE_DEVICES=4,5,6,7 python -m torch.distributed.run --standalone --nnodes=1 --nproc_per_node=4 /tmp/ddp_test.py`。
- NCCL在rank初始化后于`ncclCommInitRank`触发rank0 SIGSEGV；torchrun随后终止其他rank。
- 使用`NCCL_P2P_DISABLE=1 NCCL_IB_DISABLE=1 NCCL_SOCKET_IFNAME=ens34`后，2卡组合4,5、5,6、6,7仍复现SIGSEGV。
- Gloo GPU测试也在collective阶段异常退出。
- DDP ASR run `runs/whisper_medium_full_ddp_s42_lr1e5_20261014_v1`只执行依赖检查和M0启动，`m0_exit_code=1`，无正式baseline；原日志、启动器状态和DDP代码哈希留服务器。

后续修正了DDP代码：在`dist.init_process_group('nccl')`之前显式执行`torch.cuda.set_device(local_rank)`，并重新运行四卡最小测试；仍在`ncclCommInitRank`阶段SIGSEGV。由此排除“进程本地GPU绑定顺序”这一脚本原因，当前更可能是服务器驱动/NCCL/多卡拓扑或运行环境问题。

## 处理决定

停止并保留此前四个独立seed/三学习率run的日志和checkpoint，不把DDP失败伪装成模型失败。为继续用户已授权的准确率实验，回退为GPU4/5/6/7各跑一个Whisper-medium、LR=1e-5的独立seed。此回退测试参数稳定性和最终均值，不能缩短单模型墙钟时间；每个run仍使用全量107.397小时、完整dev选择和相同评分。

真正的单模型多卡加速需要管理员修复服务器NCCL/驱动/容器通信环境，并先通过独立2卡/4卡collective测试，再在新run中重新做M0；不能直接复用本次DDP失败的checkpoint。当前fallback2四个独立LR=1e-5 run已重新启动，作为准确率和seed稳定性实验。
