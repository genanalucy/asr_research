- checkpoint 原子写入 model/optimizer/scheduler/RNG 与数据训练 contract；失败抛出并记录 failed，正常早停记录实际 step 与 stopped_early。

## 非启动阻塞限制

1. 原审查发现的早停计数恢复问题已修复：`stale_evaluations` 和 `optimizer_seconds` 写入 checkpoint 的 `training_state` 并直接恢复，不再依赖 `early_stopping.json.step` 恰好匹配。
2. checkpoint 不保存 DataLoader 当前 shuffle 位置，恢复不保证逐 bit 相同训练轨迹，应按实现披露。
3. 恢复到一个新输出目录没有复制 `best` 时，历史 best CER 仍恢复，但结束阶段需要该 `best` 目录。此次只从原始模型 fresh 启动；续训应使用原输出目录并保留最佳模型。
4. epoch 是近似曝光数，尾批次不足 batch 时有轻微误差；正式预算需按实际过滤训练条数计算，记录实际停止 step，不能把早停后的结果称为完成 8 epoch。
5. 完整 dev 上反复选择 checkpoint 是开发集用途，不能当最终 test 泛化结果。大模型与学习率最终比较应冻结方案后再一次性使用 test。
