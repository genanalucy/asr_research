# 实验方案 v0：Beyond WER 的低资源壮语 ASR

制定日期：2026-10-13。本版结合项目文献综述与同日服务器数据盘点，已更新两种语言的规模；完成身份、重复来源与标签冲突复核后，再冻结切分、模型版本和训练预算。

**数据已于2026-10-13盘点：** 壮语约120.99小时、26个已由用户确认的说话人前缀；去重并暂排标注冲突后的结构候选约120.77小时。瑶语约45.79小时，按文件去重约39.93小时，暂排冲突后约37.83小时；来源重叠和身份候选尚未核实。详见 `docs/数据盘点-2026-10-13.md`。本版已修正不可行的“20小时单说话人”和“固定8人100小时”条件；正式切分尚未冻结。

## 一、拟定题目

中文：**小时数还是说话人数？低资源壮语 ASR 的说话人多样性、数据规模与音系可解释评测**

英文：**Hours or Speakers? Disentangling Speaker Diversity, Data Scale, and Phonological Errors in Low-Resource Zhuang ASR**

如果明天确认说话人数不足约8人，则退回保守题目：**超越 WER：面向低资源壮语 ASR 的说话人隔离、数据规模规律与音系可解释评测**。

## 二、研究问题与主张

### RQ1：小时数还是说话人数

在总训练小时数相同的情况下，增加说话人多样性是否比增加同一说话人的录音时长更能改善未见说话人的识别？在固定说话人数时，5、20、50、100及全部训练小时的收益曲线如何？

**H1：** 跨说话人测试下，小时数和说话人覆盖存在不同的边际收益；同一说话人的额外录音可能主要改善域内表现，随机句级切分会高估泛化能力。

### RQ2：WER/CER 与音系错误

WER/CER 是否掩盖了声母、韵母、音节和声调层面的差异？FER/TER 是否会改变模型排序或揭示传统指标看不到的瓶颈？

**H2：** 在声调和音节标签可靠时，音系指标能解释至少一部分词面错误；如果模型排序不改变，也报告这一评测边界，不强行宣称有效。

### RQ3：预训练模型的数据效率

Whisper-small、XLS-R-300M 或 wav2vec2-XLSR 等路线在不同训练小时数下的数据效率是否不同？

**H3：** 跨语言预训练路线在低小时数下优于从头训练，但优势受 tokenizer、语言覆盖和说话人划分影响。

## 三、数据协议

1. 以说话人为首要切分单位，目标为 train/dev/test = 80/10/10；若说话人数不足，改用原始长录音、文档或时间隔离，并在论文中明确限制。
2. 同一长录音切片不能跨集合；重复提示文本另做文本隔离分析，不能与普通测试混淆。
3. 固定 dev/test，构造两组训练子集：A组固定总量5h，比较1/2/4/8名说话人；B组固定8名说话人，比较5/10/20h。16人或30/40h扩展点必须由留出后每人可用时长决定，不能用重复采样填足独立小时数。记录说话人集合抽样种子与模型训练种子，匹配文本覆盖和录音域；全量点报告实际训练集时长。
4. 文本预处理在查看测试结果前冻结：Unicode NFC、空白、标点、数字和大小写规则写入脚本。
5. 并行保存保调原文、规范化文本和必要的去调版本。删除调号只能作为独立评分条件，不能为了提高分数临时处理。
6. 明天必须记录：语言变体、有效小时数、句数、说话人数、录音域、转写者、音节/音素/调号规则和数据许可。

## 四、模型和基线（按 4 张 L20 扩展）

### 必跑

1. **XLS-R-300M + CTC**：跨语言编码器主基线。
2. **XLS-R-1B + CTC**：容量扩展和大模型数据效率对照，只有显存和实现稳定时加入。
3. **Whisper-small/medium + LoRA 或受控全量微调**：序列到序列主线。

### 条件允许时

4. **Whisper-large-v3 + LoRA**：只做全量数据的高容量 stress test，不进入所有小时数和所有 seed，避免把显存规模误当成方法贡献。
5. **Conformer/CTC 从头训练**：用来区分预训练收益；可放在 20/50/all 小时。
6. **MMS-300M/1B**：只有在官方 checkpoint 与具体壮语变体匹配时才加入，不能仅凭语言名称判断覆盖。

所有模型统一采样率、数据划分、early stopping 规则和验证集。训练预算按模型族单独预注册，不能让大模型获得无限调参机会。记录参数量、显存、训练时长、有效更新数、吞吐和每个实验的 GPU 时数。

四张 L20 的并行安排：GPU0 跑 XLS-R-300M，GPU1 跑 Whisper-small/medium，GPU2 跑大容量或 Conformer，GPU3 跑重复 seed、MMS 或错误分析前的复核任务。不同模型族不能共享会改变结果的缓存或测试预测。

## 五、指标

### 主指标

- 保调 CER；
- 原始 WER；
- 规范化 WER。

### 条件指标

只有在语言学映射可靠时才计算：

- 音节错误率；
- Feature Error Rate：声母、韵母、尾音、调类等特征分别统计；
- Tone Error Rate；
- 按说话人、调类、录音域的混淆矩阵。

每个音系指标必须记录标签来源、音节对齐规则、插入/删除处理和分母。若调号或音节边界不可靠，取消 TER，不制造声调标签。

统计上报告按说话人的宏平均、按句子的微平均，以及配对 bootstrap 95% 置信区间。多 seed 时报告均值和标准差，并比较模型排序的 Spearman 相关。

## 六、主表和图

1. **主结果表**：模型 × 全量数据，raw/norm CER/WER，若可行加入 FER/TER。
2. **说话人多样性表**：固定5h下 speaker 数量对 CER/WER 的影响。
3. **小时数曲线**：固定8人下5/10/20h，及单独标明说话人覆盖的全训练集规模曲线。
4. **泛化差距图**：同 speaker 与 held-out speaker 的差异，以及随机句级切分的乐观偏差。
5. **音系错误图**：声母、韵母、尾音、调类混淆热图。
6. **误差案例表**：典型插入、删除、同音混淆、调类混淆和正字法差异。

## 七、执行顺序

### M0：数据和指标验收

- 生成说话人、录音、句子、时长清单；
- 检查重复音频、重复文本和跨集合泄漏；
- 冻结文本规范化规则；
- 用一个极小子集做过拟合测试；
- 对指标脚本做人工样例单元测试。

**停止门：** 小集合无法过拟合，或指标脚本无法稳定解析，先修数据和评测，不进入大规模训练。

### M1：快速基线

- 5小时壮语训练集；
- XLS-R-CTC 和 Whisper-small；
- 固定 dev/test；
- 每个模型先跑一个 seed。

目标是确认数据管线、显存、训练速度和指标方向。

### M2：小时数—说话人数正交实验

- 先跑固定5小时、不同 speaker 数的 A 组；
- 再跑固定8名 speaker、5/10/20小时的 B 组；
- 三个主模型族，关键格至少3 seeds；
- 输出“每增加一倍小时数”和“每增加一倍 speaker 数”的相对变化及 speaker-bootstrap 置信区间。

### M3：稳健性和音系诊断

- 对 50/all 小时关键配置跑 3 seeds；
- raw vs normalized 文本评分；
- speaker、domain、音系类别分层；
- bootstrap 置信区间；
- 生成错误热图和案例。

### M3.5：模型容量和预训练路线

- 在固定的 20h、50h、all 小时和固定 speaker-disjoint 划分上比较 300M、1B、Whisper-small/medium；
- Whisper-large-v3 只跑 all 小时的 LoRA stress test；
- 报告参数量、训练 GPU 时数和每小时标注数据的收益，不能只报告最终分数；
- 用配对 bootstrap 检验大模型是否在未见说话人上稳定优于小模型。

### M4：可选瑶语迁移 pilot

当前瑶语结构候选约37.83小时，已达到值得考虑第二语种的规模；但需先确认具体变体、来源重叠、说话人身份和同音频转写冲突，再执行：

- target-only 瑶语微调；
- 壮语预适配后瑶语微调；
- 直接多语言基线；
- 1h/5h/all 瑶语数据点。

若瑶语少于约5小时、只有单说话人或文字规则不清，M4 只作为趋势和失败模式，不写成双语主线。

## 八、暂不采用的主方法

暂不把“声调辅助任务、动态门控、F0 课程学习、音素边界增强”作为第一主线。这些方法已有 Bribri、SITA、T-SANDHI、Bantu 和粤语近邻。只有在完成基线、证明壮语的主要瓶颈确实是声调，并补齐直接近邻全文后，再设计轻量声调增强消融。

## 九、失败判据与改道

- speaker-disjoint 结果远差于随机切分：优先写数据泄漏和说话人记忆问题；
- FER/TER 标签不可靠：改为 phonologically informed 的音素/音节错误分析，取消 TER；
- WER/CER 与 FER/TER 排序完全一致：报告评测边界，把重点转为规模规律和错误解释；
- 单 seed 提升小于 bootstrap 不确定性：不宣称方法有效；
- 瑶语迁移没有稳定收益：保留为负结果或删除，不强行讲语言亲缘因果。

## 十、算力扩大后的可选扩展

### 1. 轻量音系多任务 pilot

如果转写能可靠解析音节和调类，可以在 XLS-R/Whisper encoder 上增加音节、音素或调类辅助头，比较：主 ASR loss、ASR+音节、ASR+音节+调类。它只作为受控 pilot；普通多任务声调监督已有直接先例，不能因为用了更多 GPU 就宣称方法首创。

### 2. 更完整的统计重复

核心 50h/all 配置跑 5 seeds；A/B 两组正交条件跑 3 seeds；小规模 pilot 只跑 1 seed。用 speaker-bootstrap 和 paired utterance-bootstrap 分开报告，不把大量 seed 当作独立说话人样本。

### 3. 瑶语迁移矩阵

如果瑶语至少约10–15小时、至少5名说话人且变体明确，可做 target-only、Zhuang-pre-adapt、multilingual-joint 三组，并在 1/5/all 小时下跑 3 seeds。若瑶语仍低于这个门槛，只做 1–2 个 pilot 点。
