# 壮语与瑶语低资源语音识别文献综述（第一版）

整理日期：2026-10-13。本文是面向选题和实验设计的叙述性综述，不是声称穷尽全部文献的系统综述。当前已知条件是：壮语语音—原文转写配对数据超过120小时，瑶语数据可能明显更少；具体语言变体、说话人数、录音类型、转写规范和 GPU 配置待明天核对。

## 1. 结论摘要

现有研究不支持把“第一次做壮语/瑶语 ASR”“第一次使用音素监督”“第一次加入声调任务”作为论文贡献。勉语已经有直接的低资源 ASR 研究；Bribri、Yoruba、台湾闽南语、Hmong 和非洲语言研究也已经覆盖了显式声调转写、声调辅助任务、声调敏感表示和声调错误评价。

最适合当前资源条件的主线是：

> **建立一个按说话人隔离、按训练小时数扩展、同时报告词/字错误和音系/声调错误的壮语 ASR 基准，并检验音系特征指标是否揭示传统 WER/CER 隐藏的差异。**

这条线的优点是可以先用可靠基线完成，创新主要来自语言资源、评测设计和可解释的错误分析，等明天确认声调标注和音系映射后再决定是否增加方法模块。120小时以上壮语数据足以支持 5/20/50/100 小时规模曲线、多说话人测试和多个随机种子；如果瑶语太少，可以将瑶语定位为迁移/外部验证，而不是与壮语强行做对等主语种比较。

声调保护增强可以作为第二主线，但查新风险更高。已有工作已经研究显式调号、音节—声调辅助、动态门控、F0 课程学习和音素感知增强。只有在目标语言的声调标签可靠，并能与最近的粤语、闽南语和 Hmong 工作明确区分时，才适合把它提升为核心方法。

## 2. 低资源和濒危语言 ASR 的经验

最直接的近邻是 Iu Mien（勉语）研究。Dong 等人在约9.7小时、9761句、单女性说话人的 MightLJSpeech 上比较子词、音素和弱音素监督的多语言预训练；音素监督路线在低资源条件下更有数据效率。这意味着“第一次做瑶语 ASR”不能成立，“音素监督本身创新”也不能成立。它仍然是本项目最重要的基线来源，因为具体勉语变体、目标文字和用户的瑶语变体可能不同，差异需要用数据核对，而不能仅按民族名称推断。

Yolóxochitl Mixtec 的 EACL 研究更接近用户的资源规模：训练集约92.46小时、34名说话人，并报告10、20、50和约92小时的规模曲线。Conformer 在完整测试集上达到约7.7 CER、16.0 WER。该研究说明，超过100小时的濒危语言语料足以写出有说服力的数据规模和说话人隔离实验；论文的贡献重点是文档化和可复现实证，而不是一个复杂的新架构。

Boulianne 的研究比较了11种濒危语言的音素转写架构和数据规模，说明极短时长下模型、音素单位和说话人设定会显著影响结论。Tusom2021 则提供了带音素转写和三声调背景的濒危语言资源先例。ManWav、Kichwa、Ikema Miyakoan 和 Neo-Aramaic 等工作进一步表明，论文必须明确写出说话人数、录音域、转写质量和评测是否跨说话人。

这些研究共同给出三条实验底线：

1. 同一说话人的切片不能同时进入训练和测试，否则结果只能解释为说话人相关的识别能力。
2. 朗读语料、自然会话、圣经朗读、田野录音和广播剧的域差异必须单独记录，不能混成一个“语言性能”。
3. 转写规范、正字法、调号和词边界会直接影响 WER/CER；原始转写和规范化转写应分开评分。

## 3. 预训练模型和跨语言迁移

wav2vec 2.0、XLS-R、MMS 和 Whisper 构成当前应有的基础基线。XLS-R 和 MMS 更适合做跨语言 CTC/编码器路线，Whisper 适合做序列到序列适配；不能只用一个模型就把结果解释为语言本身的难度。

Whistle 的弱音素监督和 IPA 桥接是勉语论文的重要上游；但“使用 IPA 连接多语言”已经有先例。ATDS 进一步用声学伪 token 选择迁移供体，说明语言亲缘关系不是唯一的迁移标准。关于语言亲缘关系的近期研究也提醒：相关语言先适配不保证在目标语言上带来收益，迁移实验必须和直接目标语适配、随机供体及相同训练预算进行比较。

如果瑶语数据很少，合理的设计是：

- 壮语作为主实验语言，做完整基准、规模曲线和错误分析；
- 瑶语作为低资源外部验证或迁移目标，报告少量数据下的趋势和失败模式；
- 只有在瑶语具体变体、文字体系和说话人数量足以支撑比较时，才把两种语言并列成双语主线。

不建议一开始使用 7B 级语音/语言模型或复杂 ICL。已有低资源工作表明，外部语言模型和检索式重排序可以改善部分语言，但它们需要公平的 n-gram/Transformer LM 基线、独立文本来源和严格的数据隔离，工程成本高且不一定比更简单的解码适配更有说服力。

## 4. 声调、音系和评价指标

Bribri 研究已经显示，显式声调转写以及把声调和元音分开建模可以改善极低资源 ASR；因此“给壮语加调号”本身不是新意。Yoruba 研究则给出相反方向的警示：带调号的输出在多个模型上反而显著变差，去调号后的 WER/TER 更低。这说明调号是否有益取决于 tokenizer、预训练表示、正字法和评价定义，不能预先假设“声调越显式越好”。

T-SANDHI 已经研究了本调/表层声调双流、声调辅助任务和动态门控；SITA 已经研究了说话人不变和声调敏感表示；Tone-Conditioned Curriculum Learning 已经用整句 F0 统计、门控适配器和课程学习；粤语近邻则研究了音素感知增强。因此以下表述都不能直接作为首创：

- 增加声调辅助任务；
- 将音节拆成音节加调类；
- 使用 F0 统计做课程学习；
- 使用动态门控融合声调分支；
- 在音素边界附近进行增强保护。

更稳妥的切入点是改进评价和诊断。AfricaNLP 2026 的工作把 WER、CER、Feature Error Rate（FER）和 Tone Error Rate（TER）并列，说明 WER 接近100%时，模型仍可能正确识别相当一部分音系特征。对壮语/瑶语，可以根据语言学家的音系表建立：

- CER、原始 WER、规范化 WER；
- 音素或音节级 Feature Error Rate；
- 以音节为单位的 Tone Error Rate；
- 按调类、声母、韵母、尾音和说话人的混淆矩阵；
- 说话人隔离和不同训练小时数下的分层结果。

这要求明天确认：转写中是否有可靠的调号、声调与音节边界是否可自动解析、壮语和瑶语的文字是否一一对应音系单位。F0 可以作为弱诊断特征，但不能把整句 F0 离散化后直接称为词汇声调标签；F0 同时受到说话人、语调、发声态和噪声影响。

## 5. 适合本项目的候选论文方向

### 方向 A：壮语 ASR 的音系可解释评测与数据规模规律（首选）

核心问题：传统 WER/CER 是否低估了壮语识别中“音系特征已识别但词形错误”的情况？随训练小时数、说话人数量和模型类型变化，FER/TER 是否比 WER 更稳定地反映能力？

最小实验：

- Whisper-small 或同级模型；XLS-R/Wav2Vec2-CTC；MMS 作为多语言基线；
- 5、20、50、100小时嵌套训练子集；
- speaker-disjoint 验证和测试；
- CER、规范化 WER、保调 WER、FER、TER；
- 按音素、音节、调类、说话人和录音域做错误分析。

这条方向不要求先发明新网络，最适合先拿到稳健结果。若结果显示 FER/TER 与 WER 得出的模型排序不同，就有清楚的论文问题；若排序完全一致，也能形成有价值的负结果和评测边界。

### 方向 B：壮语到具体瑶语变体的低资源迁移

核心问题：语言亲缘、声学相似性、文字/音系相似性和多语言预训练覆盖，哪个因素更能预测迁移收益？

前提是明天确认瑶语具体变体及其小时数、说话人和文字规则。实验至少应包括直接瑶语适配、壮语预适配、相关语言预适配和不相关语言/随机供体控制，并匹配额外语音小时数和训练预算。若瑶语少于几小时，主张应收缩为 pilot 或外部验证，不能宣称完整的双语结论。

### 方向 C：声调/韵律保真增强

只有在声调标签可靠、F0 提取质量可控并取得粤语近邻全文后再考虑。核心比较应包括无增强、调优后的普通 SpecAugment、等掩码量随机保护、所提保护增强，另加声调错误而非只报 WER。必须排除“增强更温和”或“有效破坏更少”导致的伪增益。

## 6. 明天拿到数据后需要先确认的字段

- 壮语具体方言/地区、瑶语具体语言或变体；
- 每种语言的有效配对小时数、句数、说话人数和性别/年龄分布；
- 朗读、自然会话、访谈、广播或田野录音的比例；
- 转写是原语言文字还是中文翻译，是否有调号、音节边界、词边界；
- 是否存在同一说话人的重复提示、同一长录音切片或跨集合泄漏风险；
- 是否另有未配对语音、目标语文本、词典、音素表或语言学标注；
- GPU 型号、显存和可接受的训练时间；
- 数据是否允许公开，或只能公开评测脚本与统计摘要。

## 8. 文献管理建议

当前不需要立即安装 Zotero MCP。项目已有 `references.bib`、`pending-fulltext.bib`、`literature-catalog.json`、`SHA256SUMS.txt`、每篇论文的 `metadata.json` 和下载/目录脚本，足以完成第一轮综述和可追溯下载。

进入正式写作阶段后，如果文献超过约50篇，或需要在 Zotero 与 BibTeX 之间双向同步，再考虑 Zotero + Better BibTeX 或 Zotero MCP。当前应优先避免 arXiv 与正式会议版本重复计数，并在正文引用前核对 DOI、作者、年份和正式出版信息。
